# 45 — StepUp 原五档礼包、HUD 与武器横幅

唯一输入为 adb 提取的 `com.Chodun.CatGunner 1.1.61 / vc257` ARM64 原生库、匹配 metadata 和冻结 Main。旧 XAPK 不参与。工程为 Unity 6000.4.10f1，商业交易沿用用户授权的明确本地模拟。

## 原生规则

`native-stepup-client-reviewed/` 包含42个业务方法及6个异常辅助查询，48个唯一查询均完成。初次导出时 `StepUp.Hud_Reload` 与 `StepUp_Hud.Reload` 的扁平文件名冲突，初始产物保留在 `native-stepup-client-first-label-collision/`；本范围改用类/方法双下划线后重新导出，不能将第一次结果称为完整。字符串插值在 `reports/stepup-literals.json` 中逐项解析。

- 起始日期为空/无效时未启动；首次打开或符合横幅条件时写入一次开始时间。未启动剩余7天，启动后为 `max(0, start + 7 days - now)`。
- 收藏数组索引10及以后任意为true即满足 Degree>=2。该条件来自原 `Gun_manager.Has_Degree_Or_Higher`，不是当前背包持有条件。
- 五档按顺序解锁：当前档未买且前档已买；第一档无需前档。**原 Is_Purchasable 不检查期限或库存**。期限只控制HUD/横幅可见性，已打开页面在到期后的顺序资格仍独立判断；库存满由点击流程单独拒绝。
- 五档枪械为23、28、33、39、44，附赠钻石为0、200、400、600、1000。现金按钮使用既有本地购买账本，不写真实收据/交易记录。
- 首档前 HUD 显示原价格图，购买首档后改紧凑时间；全部买完或到期隐藏入口。武器横幅预览当前下一档枪械，首档价值倍数12、之后5。原 Purchased 装饰的冻结默认值保留，不推测额外原生控制逻辑。
- 大于等于一天完整时间为 `{0}d {1}:{2:00}:{3:00}`，不足一天为 `{0}:{1:00}:{2:00}`；HUD按天/小时/分钟分别使用原三种紧凑格式。
- 库存满复用原 Alert 的 `Gun/InventoryFull` 原文本与失败音5；已购/未解锁点击不发奖。关闭使用原持久回调。

## 场景和本地适配

通过 Editor API 合入原 StepUp 与 StepUp_obj 两分支的215个原对象，恢复10份原组件/81项引用、13级枪械展示引用与8个原按钮回调。五个原脚本 meta 与冻结导出一致；源切片中33个尚未支持的插件/服务组件隔离，不以空壳伪装原逻辑。现有菜单相对顺序及序列化布局保留；新增对象按原层级插入。教程 HUD 为9/11处绑定，轮前已为9/11，不能称为本轮新增教程绑定。

`OriginalStepUpOffer` 保存资格/日期模型；`StepUp` 使用0.25秒unscaled刷新。真实服务时间未恢复，当前为本机UTC时钟；价格沿用原序列化展示，不代表当前商店报价。14语言文本取自原表，本地选择简体/繁体/英文，完整I2仍未恢复。

首次行为测试全部通过后，GPU检查发现中文“后解/价”的JP后备字体仍使用原不兼容Shader。已保留修复前图片，修复递归后备字体材质为现有官方TMP兼容Shader，保留原字体和图集；增加实际字形mesh材质检查；第二次GPU复验发现旧JP图集/度量导致部分字形极小，最终六处动态文本直接使用包内Noto Sans SC字体及原描边兼容材质，字形高度断言与实际GPU复验通过。场景审计发现首次合入改变旧父对象子序，随后保存又重写菜单LayoutGroup驱动字段；已通过Editor API恢复，最终严格文档差异报告为准。
