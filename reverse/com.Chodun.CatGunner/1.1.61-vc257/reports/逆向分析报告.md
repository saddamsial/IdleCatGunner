# Cat Gunner 1.1.61 首轮逆向分析

正确目标为 **com.Chodun.CatGunner 1.1.61 / versionCode 257 / arm64-v8a**，来自用户手机的原签名主 APK 和 ARM64 拆分包。用户确认其为两段森林录屏的游戏；包内也找到森林地图、猫、树木、武器和升级的资源及脚本。原始 SHA-256、ZIP 完整性与手机复制一致性见 apk-inventory.json。旧 com.gear2.catdiver2 的 66 张表和 UnityClient 未用于本构建。

## 已完成

- 两个 APK 展开为 2,001 个文件，逐文件哈希记录到 extracted-input-manifest.json；原包没有改动。
- Unity BuildSettings 独立确认 **6000.0.61f1**，原主场景为 `Assets/Scenes/Main.unity`。native 为 ELF64 AArch64 IL2CPP。
- 原始 UnityFS 资源正常解析：157,237 个对象，包含 39,920 个 GameObject、33,087 个 MonoBehaviour、3,918 个 MonoScript、670 个 Sprite、160 张 Texture2D、17 个 AudioClip、18 个 AnimationClip、14 个 AnimatorController。指定类型读取无错误。GameObject 数量不等于 Prefab 数量，当前未做 Prefab 分类或完整导出。
- 已提取 10 张原始 Sprite 预览，包含 Cat_Gun、Cat_icon、Road_Forest、Field_Forest、Forest_Grass 和设置/武器图标。源文件/pathID/尺寸与输出哈希见 asset-preview-manifest.json。
- 定位了本构建的 metadata 加载链，并对 408 字节乱序头和七段数据复现原 native 的变换，共输出 9,948,532 字节区域数据。原 metadata 保留不变，变换结果在 transformed/；它们是中间产物，不能直接当成标准 global-metadata.dat 交给通用工具。
- 读通并校验了 136 个 image、18,762 个 TypeDefinition、142,632 个 MethodDefinition、79,822 个 FieldDefinition。所有类型的 UTF-8 名称、字段/方法范围、关联的字段 token、方法 token 与 declaring type 检查通过。
- 原资源中的 415 个 Assembly-CSharp MonoScript 对象有 399 个唯一 assembly/namespace/class 短身份，metadata 中均有候选：398 个可唯一匹配；Gun 有三个同名类型，需结合 declaring type、继承和原组件字段进一步定位，不能按短名称直接绑定 GUID。总共记录 401 个候选类型。该程序集包含 815 个类型和 5,873 个方法 token。
- 用原 ELF relocation 与 CodeGenModule 建立地址映射：游戏主程序集 5,873 个方法 token 均对应表项，5,780 个非零地址均在 executable PT_LOAD 段。进一步校验了 132 个非空 codegen module，映射 127,186 条非零指针。SDK 部分只保留签名/地址导航，没有反编译它们的业务实现。
- 对 14 个局部游戏入口及 6 个异常 helper 做了 Ghidra 查询。首 16 字节逐项匹配原 ELF，preferred VA、文件偏移和 Ghidra +0x100000 的重定位关系已验证。异常 helper 通过最终 __cxa_throw 路径确定不返回，返回异常对象的 resolver 没有被误标；之后重新生成局部伪代码。

## 保护层与可行性

资源是标准 UnityFS，已有解析成功证据，无需套用旧包的配置解密。metadata 为本构建定制格式：乱序字段、偏置 offset、查表/XOR 流变换分区域加载。native IL2CPP API 有随机名称导出，但 codegen module 和正常 ARM64 指令仍可定位。不能由一个文件头异常就称为整个游戏不可逆向，也不能由当前解码成功推断其他保护层已全部解决。

当前类型/方法/字段布局已得到交叉验证，剩余 metadata 表、Il2CppType/参数类型、field-offset table 和原属性 schema 尚需完成适配。主方法地址已可用于针对性恢复，无需先进行手机运行时注入或读取私有存档。

## 玩法入口和已读规则

主要入口为 Gamemanager、Tree_manager、Tree、Cat、Cat_manager、Gun_manager、Upgrade_manager、Setting、SaveSystem。对应字段和原方法导航见 original-script-schema-index.json；具体 native 地址见 game-method-map.json。

原 native 的升级价格分支已读到：5000 级及以下先做 double 的 `50 × Math.Pow(1.38, level)`，再转 InfVal、调用 ToPrecision(3)；超过 5000 级存在另外的 InfVal 幂与乘法分支。保持 double 运算和原精度 API 的顺序，InfVal 的特殊值/舍入尚未验收。攻速 native 存在速度分母 100–10000、冷却时间 0.05–2 秒限制，以及重生/升级/关卡/Buff 的不同分支。更多证据和边界见 [原规则索引](../original-game-rules/00_INDEX.md) 与 [局部规则](../original-game-rules/01_UPGRADE_AND_STAGE.md)。

Settings 三个入口与录像的 BGM/Sound/Vibration 按钮相符。完整 UI_Reload 仍有 PIC/间接调用反编译警告，只能确认开关位与局部调用，不应宣称整页恢复。关卡数组、缓存与范围外计算已找到，刷树、完整伤害、结算和存档仍需闭合。

## 验收边界与下一步

本轮是原包解包、metadata 适配、资产/地址导航和局部 native 分析。**尚无 Cat Gunner 的可玩 Unity 工程，尚未恢复完整 C# 方法，也没有新 APK 或手机玩法一致性验收。** 14 个 completed 结果仅说明产生伪代码；结构体 ABI、未解析调用、UI 警告和方法依赖需要逐项核对。native-gameplay/ 是异常 helper 修正前的诊断输出，后续阅读以 native-reviewed/ 为准；原 loader 的伪代码也需结合汇编而非独立当成源代码。

后续顺序：补齐 native 类型/字段偏移与参数 → 为原 MonoBehaviour 建立准确 schema → 独立导出 Main 场景/原 UI/地图和角色 → 用用户现有 Unity 6000.4.10f1 新建独立恢复工程 → 首先恢复设置和最小森林战斗闭环。旧海底 UnityClient 保留独立，不覆盖、不混用。

广告、IAP、分析/归因 SDK、远端后台和反作弊绕过不在本轮恢复范围。没有读取或修改手机存档，没有对其他 Unity 工程做操作，本轮未 commit/push。
